# 一、RDMA Write 是什么？

一句话极简定义

RDMA Write 是硬件驱动的单边远程内存写入操作。

本地机器的RDMA网卡，可以绕过双方CPU、绕过双方操作系统内核协议栈，直接把本地内存的数据，点对点写入远端机器的物理内存。

通俗类比（秒懂）

TCP / RDMA Send：我给你发快递，你必须在家收件、拆快递、处理包裹，两个人必须配合。

RDMA Write：我有你家房门钥匙，直接开门把东西放进你家里的指定柜子，你全程不在家、不用知情、不用动手。

全程远端CPU零介入，这就是RDMA Write碾压传统网络的核心底牌。

---

# 二、RDMA Write 最核心的 3 个特点（附带底层原理）

## 1\. 纯单边操作，远端软硬件全程无感知

先分清核心概念：双边操作 vs 单边操作

TCP、Socket通信、RDMA Send 全部属于强双边通信：

发送端发包

远端内核接收报文，中断唤醒CPU

远端应用程序调用recv接口，从内核缓冲区拷贝数据

双方CPU都要消耗算力处理收发逻辑

而RDMA Write是纯单边：

远端只需要提前做一次内存注册（MR），把内存权限开放给RDMA网卡。后续所有写入动作，远端操作系统、远端CPU、远端业务进程，全部不需要参与任何收发逻辑，无中断、无系统调用、无业务代码处理。

关键补充：内存注册是一次性前置开销，一次注册可反复读写，不会影响单次传输时延。

## 2\. 硬件直通零拷贝，彻底旁路内核与CPU

传统TCP完整数据路径（两次拷贝+多次CPU中断）

业务应用内存 → 内核socket缓冲区（CPU拷贝1） → 网卡DMA缓冲区（CPU拷贝2） → 网络对端内核缓冲区 → 对端业务内存

痛点：两次内存拷贝、频繁硬中断、内核协议栈处理报文分片/重传/校验，CPU开销爆炸，大吞吐场景下CPU会被网络打满。

RDMA Write硬件直通路径（全程无CPU参与拷贝）

本地业务内存 → 本地RDMA网卡DMA → 网络链路 → 远端RDMA网卡DMA → 远端业务内存

全程无内核介入、无CPU数据搬运、无系统调用、无内存拷贝，所有报文重组、重传、流量控制全部由网卡硬件RoCE芯片完成。

## 3\. 原生无远端通知，默认“静默写内存”（最高频线上坑点）

这是90%新手落地RDMA都会踩的坑：

RDMA Write只会把数据写入远端内存，不会给远端产生任何完成队列事件CQE，不会触发远端中断。

也就是说：数据已经稳稳写到你内存里了，但是你的程序完全不知道什么时候写完、数据是否就绪。

工程上两种标准补全通知方案

Write with Immediate（带立即数写）：写完数据后，硬件自动给远端推送一个携带4字节立即数的CQE事件，远端收到事件即可判定数据就绪；适合绝大多数大数据同步场景

后置一条RDMA Send：大批量Write传输完成后，发送一条小Send消息做同步确认；适合超大文件分片传输场景

# 三、RDMA三大原语：Send / Write / Read 完整横向对比（补齐你缺少的Read内容）

很多文章只对比Send和Write，漏掉Read，导致大家始终搞不清三者选型边界，这里一次性补齐。

| RDMA原语 | 操作模式 | 远端是否产生CQE | 是否需要远端业务配合 | 传输内容 | 性能损耗 | 适用场景 |
| --- | --- | --- | --- | --- | --- | --- |
| 
## RDMA Send

 | 双边操作 | 是 | 必须提前注册接收缓冲区 | 消息报文+立即数 | 最高，远端CPU需要处理中断 | 控制指令、心跳、信号通知、小消息交互 |
| 

## RDMA Write

 | 单边写内存 | 默认无，可追加立即数 | 不需要 | 纯裸数据流，无消息头 | 最低，远端零开销 | 大数据搬运、梯度同步、存储副本 |
| 

## RDMA Read

 | 单边读内存 | 远端完全无CQE | 不需要 | 从远端拉取裸数据 | 略高于Write，存在请求往返时延 | 按需拉取远端数据、元数据查询，极少用于大批量传输 |

极简选型口诀（直接背）

发指令、发通知、做握手 → 用Send

推数据、传文件、同步参数 → 用Write

主动拉取远端数据、按需查询 → 用Read

# 六、核心灵魂问题：为什么AI训练坚决不用Send/Read，只无脑用Write？

结合大模型训练场景，直击业务本质：

AI训练需要大批量梯度、参数单向推送：每张卡需要持续把本地计算出的梯度推送到其他节点，是纯单向数据流，不需要远端回应，完美匹配Write单向推送能力

不能浪费远端CPU算力：AI服务器CPU资源极其珍贵，一旦用Send，远端CPU会被网络中断抢占，直接降低模型训练吞吐，拖慢整体集群速度

Read存在RTT往返延迟：如果用Read拉取参数，每一次数据读取都要等待远端应答，叠加之后集群通信延迟暴涨

Write支持超大缓冲区批量写入：可以一次性写入MB级别的大块数据，分片少、硬件处理效率远高于Send小包交互

---

# 七、线上生产高频踩坑总结（实战必看）

直接裸Write之后业务卡死：忘记加立即数通知，业务轮询内存判断数据就绪，产生大量无效轮询开销，务必搭配Write with Imm

RKey过期导致写失败：远端内存解除注册后RKey失效，动态内存复用场景需要实时更新RKey

混用Send和Write导致内存乱序：RDMA不同QP队列消息不保序，大数据传输不要混合原语

过小数据包用Write得不偿失：小包场景内存注册开销大于传输收益，小控制消息老老实实使用Send

# 八、全文字一句话终极总结

RDMA Write = 硬件单边直写 + 全程零拷贝 + 旁路内核无中断 + 远端CPU零开销 + 单向无RTT往返。

它不是RDMA的附加功能，而是高性能分布式系统、AI算力集群、分布式存储的底层通信基石。

凡是需要高速、大批量、低开销单向数据搬运的场景，RDMA Write都是无可替代的最优解。
