大家好，我是蟹老板～

刚入行那会，我总觉得**结构体**就是简单攒几个变量，没什么技术含量。

直到后来接手大厂量产项目，看着别人几行结构体搞定硬件适配、协议解析、状态管理，我还在傻傻写一堆零散变量、冗余判断，每次调试起来都麻烦的要死。

**我才彻底悟了，C语言嵌入式的核心精髓，一半都在结构体身上。**

不管是底层寄存器配置、通信协议解析，还是RTOS架构、量产固件开发，**所有高端嵌入式工程，都是用结构体搭起来的**。

这篇文章整理了嵌入式开发中最值得精通的 28 类结构体。聊聊它们在真实项目里到底怎么用，哪里容易翻车。

## 一、基础底层篇（4个）

### 1\. 基础标准结构体｜数据打包、批量参数管理

最普通的结构体，反而是使用频率最高的。

假设我们要保存一个温控模块的运行参数。初学者很容易把变量全部拆开。

```
float target_temp;
float current_temp;
float kp;
float ki;
float kd;
uint8_t enable;
```

这样写暂时没问题。

等模块越来越多，变量名开始满天飞，函数参数也变成一长串。调用一次初始化函数，像报菜名一样。

```
void temp_init(float target,
               float current,
               float kp,
               float ki,
               float kd,
               uint8_t enable);
```

我看到这种函数声明，心里通常会咯噔一下。**参数再加两个，调用者大概率就要传错位置了。**

把相关数据放进一个结构体，代码立刻清爽很多。

```
typedef struct
{
    float target_temp;
    float current_temp;

    float kp;
    float ki;
    float kd;

    uint8_t enable;
} TempController_t;
```

初始化函数也可以改成下面这样。

```
void temp_controller_init(TempController_t *controller)
{
    controller->target_temp = 25.0f;
    controller->current_temp = 0.0f;

    controller->kp = 1.2f;
    controller->ki = 0.05f;
    controller->kd = 0.01f;

    controller->enable = 1U;
}
```

**结构体真正解决的，不只是少写几个参数。它把一组具有共同生命周期和共同业务含义的数据，变成了一个整体。**

以后要增加限温值、报警状态、滤波参数，不需要把几十个函数接口全部改一遍。

```
typedef struct
{
    float target_temp;
    float current_temp;

    float kp;
    float ki;
    float kd;

    float max_temp;
    float min_temp;

    uint8_t enable;
    uint8_t alarm;
} TempController_t;
```

**做嵌入式久了会发现，函数参数数量一旦超过五六个，就该认真考虑结构体了。**

### 2\. 嵌套结构体｜分层解耦、复杂数据归类

结构体里面还能继续放结构体，这是为了把不同层级的数据分开。

比如一个电机对象，既有硬件信息，又有控制参数，还有实时状态。全平铺在一个结构体里，后期会越来越乱。

```
typedef struct
{
    uint8_t pwm_channel;
    uint8_t direction_pin;
    uint8_t enable_pin;
} MotorHardware_t;

typedef struct
{
    float kp;
    float ki;
    float kd;
    float max_output;
} MotorPid_t;

typedef struct
{
    float target_speed;
    float actual_speed;
    float current;
    uint8_t running;
    uint8_t fault;
} MotorState_t;

typedef struct
{
    MotorHardware_t hardware;
    MotorPid_t pid;
    MotorState_t state;
} Motor_t;
```

访问时，层次关系很明确。

```
Motor_t motor;

motor.hardware.pwm_channel = 2U;
motor.pid.kp = 0.8f;
motor.state.target_speed = 1500.0f;
```

看到 `motor.pid.kp`，不用翻定义也知道它是电机 PID 参数。

看到 `motor.state.fault`，也知道它是运行状态，而不是出厂配置。

我以前接过一个老项目，里面一个电机结构体塞了七十多个字段。从引脚编号到版本号，从采样值到滤波中间变量，全挤在一起。找一个过流阈值，要上下滚半天。

能跑，确实能跑。

维护起来也确实想跑，跑路的跑。

**嵌套结构体特别适合下面几种分类方式：**

-   • 硬件配置与运行状态分离
    
-   • 输入参数与输出结果分离
    
-   • 用户配置与内部变量分离
    
-   • 永久存储数据与临时缓存分离
    

**结构层级不宜无限套娃。一般两到三层已经足够。**

### 3\. 匿名结构体｜简化局部代码、消除冗余类型

有些子结构只在某一个父结构体里使用，单独给它起类型名反而显得啰嗦。

这时候可以用匿名结构体。

```
typedef struct
{
    uint32_t id;

    struct
    {
        float x;
        float y;
        float z;
    } position;

    struct
    {
        float roll;
        float pitch;
        float yaw;
    } attitude;
} RobotState_t;
```

使用起来很自然。

```
RobotState_t robot;

robot.position.x = 120.0f;
robot.position.y = 35.0f;
robot.position.z = 8.0f;

robot.attitude.yaw = 90.0f;
```

`position` 和 `attitude` 只属于 `RobotState_t`，没有必要额外定义两个全局可见的类型。

**匿名结构体适合局部归类，但别把它当成万能胶。**

如果某个结构需要被多个模块复用，还是应该给它一个正式类型。

```
typedef struct
{
    float x;
    float y;
    float z;
} Vector3f_t;
```

然后再组合。

```
typedef struct
{
    uint32_t id;
    Vector3f_t position;
    Vector3f_t velocity;
    Vector3f_t acceleration;
} MotionState_t;
```

**判断标准并不复杂：** 只服务一个父结构体，可以匿名。准备复用、传参、做接口，就老老实实起名字。

### 4\. 位域结构体｜寄存器单比特精准操作

嵌入式开发离不开位操作。

某个状态字里，bit0 表示使能，bit1 表示忙，bit2 表示故障，剩下几位还有其他含义。全靠移位和掩码写，当然没问题。

```
#define STATUS_ENABLE_MASK   (1U << 0)
#define STATUS_BUSY_MASK     (1U << 1)
#define STATUS_FAULT_MASK    (1U << 2)
```

也可以使用位域结构体，让字段更直观。

```
typedef struct
{
    uint8_t enable    : 1;
    uint8_t busy      : 1;
    uint8_t fault     : 1;
    uint8_t direction : 1;
    uint8_t mode      : 2;
    uint8_t reserved  : 2;
} StatusBits_t;
```

使用方式如下。

```
StatusBits_t status = {0};

status.enable = 1U;
status.direction = 1U;
status.mode = 2U;
```

还可以和共用体搭配，同时获得整体值和分字段访问能力。

```
typedef union
{
    uint8_t value;

    struct
    {
        uint8_t enable    : 1;
        uint8_t busy      : 1;
        uint8_t fault     : 1;
        uint8_t direction : 1;
        uint8_t mode      : 2;
        uint8_t reserved  : 2;
    } bits;
} StatusRegister_t;

StatusRegister_t status_reg;

status_reg.value = 0U;
status_reg.bits.enable = 1U;
status_reg.bits.mode = 3U;
```

**位域看起来很香，但它有一个大坑：不同编译器、不同目标架构，对位域排列顺序和存储单元的处理可能不同。** 把位域结构体直接用于跨平台通信协议，风险很高。拿它直接映射硬件寄存器，也要确认编译器行为、字节序和芯片手册。

**我个人的习惯是，项目内部状态字可以大胆用。涉及通信协议和可移植驱动，优先使用显式掩码。**

## 二、内存优化篇（2个）—— 极致节省RAM/Flash

### 5\. Union共用体结构体｜内存复用、多类型数据兼容

`union` 里所有成员共用同一块内存。

它不是多个成员同时存在，而是同一块内存可以用不同方式解释。

```
typedef union
{
    uint32_t u32;
    int32_t  i32;
    float    f32;
    uint8_t  bytes[4];
} Data32_t;
```

这个共用体的大小通常是 4 字节，而不是所有成员大小相加。

```
Data32_t data;

data.f32 = 12.5f;

uint8_t byte0 = data.bytes[0];
uint8_t byte1 = data.bytes[1];
uint8_t byte2 = data.bytes[2];
uint8_t byte3 = data.bytes[3];
```

在串口协议、CAN 数据拆包、传感器原始数据处理中，经常能看到这种写法。

不过，通过 `union` 直接观察浮点数字节布局，仍然依赖目标平台的字节序和浮点表示。绝大多数 MCU 使用 IEEE 754，但工程代码不能只靠"大家都这样"。

**共用体更大的价值，是节省互斥数据的内存。**

假设设备在不同模式下，需要保存不同的工作参数。

```
typedef struct
{
    float target_temp;
    float heating_power;
} HeatingParam_t;

typedef struct
{
    float target_speed;
    float acceleration;
    float deceleration;
} MotorParam_t;

typedef struct
{
    uint16_t frequency;
    uint16_t duty;
} SignalParam_t;

typedef struct
{
    uint8_t mode;

    union
    {
        HeatingParam_t heating;
        MotorParam_t motor;
        SignalParam_t signal;
    } param;
} DeviceCommand_t;
```

同一时刻只会使用一种模式，没必要给三套参数分别分配空间。

```
DeviceCommand_t command;

command.mode = 1U;
command.param.motor.target_speed = 1200.0f;
command.param.motor.acceleration = 200.0f;
```

**这里最好配一个类型标记，也就是上面的 `mode`。** 没有类型标记，后面的维护者根本不知道当前共用体里到底存了什么。

**共用体不是内存魔法，是一种带风险的内存复用协议。**

### 6\. const常量结构体｜出厂参数固化、零RAM占用

很多配置参数在设备运行期间根本不会变化。

比如硬件版本、默认 PID、传感器量程、产品型号、设备能力表。却有不少项目把它们定义成普通全局变量，开机时再复制一遍。

RAM 就这么一点点被吃掉了。

```
typedef struct
{
    uint16_t hardware_version;
    uint16_t product_id;

    float voltage_max;
    float current_max;
    float temperature_max;
} FactoryConfig_t;
```

把只读配置声明为 `const`。

```
static const FactoryConfig_t g_factory_config =
{
    .hardware_version = 0x0102U,
    .product_id = 0x1020U,

    .voltage_max = 28.0f,
    .current_max = 5.0f,
    .temperature_max = 85.0f
};
```

**在常见 MCU 工具链里，这类数据通常会进入只读段，最终存放在 Flash 中，不占用运行时可写 RAM。**

读取方式和普通结构体没有区别。

```
if (measured_current > g_factory_config.current_max)
{
    motor_shutdown();
}
```

还可以定义成配置表。

```
typedef struct
{
    uint8_t channel;
    float gain;
    float offset;
} AdcCalibration_t;

static const AdcCalibration_t g_adc_calibration_table[] =
{
    {0U, 1.002f, -0.015f},
    {1U, 0.998f,  0.008f},
    {2U, 1.005f, -0.021f}
};
```

我见过一个 RAM 只有 8KB 的小项目，初始化表、正弦表、菜单文本和产品参数全没加 `const`。程序一启动，RAM 使用率直接八成。

后来大家花两天排查"偶发栈溢出"，最后发现不是任务栈太小，是静态数据把 RAM 挤得只剩一条缝。

## 三、底层驱动篇（4个）—— MCU硬件开发核心

### 7\. 寄存器映射结构体｜GPIO/UART/ADC硬件地址绑定

MCU 外设寄存器通常是一段连续地址。

GPIO 可能从某个基地址开始，依次排列模式寄存器、输出类型寄存器、输入数据寄存器和输出数据寄存器。

最直接的写法是手动计算地址：

```
#define GPIOA_BASE      0x48000000UL
#define GPIOA_MODER     (*(volatile uint32_t *)(GPIOA_BASE + 0x00UL))
#define GPIOA_OTYPER    (*(volatile uint32_t *)(GPIOA_BASE + 0x04UL))
#define GPIOA_IDR       (*(volatile uint32_t *)(GPIOA_BASE + 0x10UL))
#define GPIOA_ODR       (*(volatile uint32_t *)(GPIOA_BASE + 0x14UL))
```

寄存器一多，宏定义会铺满整个文件。

用结构体映射就会更舒服。

```
typedef struct
{
    volatile uint32_t MODER;
    volatile uint32_t OTYPER;
    volatile uint32_t OSPEEDR;
    volatile uint32_t PUPDR;
    volatile uint32_t IDR;
    volatile uint32_t ODR;
    volatile uint32_t BSRR;
    volatile uint32_t LCKR;
    volatile uint32_t AFRL;
    volatile uint32_t AFRH;
} GPIO_Registers_t;
```

然后把基地址转换成结构体指针。

```
#define GPIOA_BASE      0x48000000UL
#define GPIOA           ((GPIO_Registers_t *)GPIOA_BASE)
```

操作输出寄存器时，代码接近芯片手册的表达。

```
GPIOA->MODER &= ～(3UL << (5U * 2U));
GPIOA->MODER |=  (1UL << (5U * 2U));

GPIOA->BSRR = (1UL << 5U);
```

**这里的 `volatile` 不能省。** 硬件寄存器可能在程序不可见的时刻变化。编译器不能把它当普通变量缓存，也不能随意删掉看似重复的读写。

**寄存器结构体还必须严格匹配芯片手册中的地址偏移。** 中间有保留区域时，要显式填充。

```
typedef struct
{
    volatile uint32_t CTRL;       /* 0x00 */
    volatile uint32_t STATUS;     /* 0x04 */
    uint32_t RESERVED0[2];        /* 0x08 到 0x0C */
    volatile uint32_t DATA;       /* 0x10 */
} Peripheral_Registers_t;
```

**偏移错一个字节，访问的就不是同一个世界了。**

而且它通常不会立刻报错，只会以一种很隐藏的方式让设备随机失控。

### 8\. 硬件配置表结构体｜按键、LED、外设批量初始化

当板子上只有一个 LED，写几个宏就够了。

当板子上有八个 LED、十几个按键、四路继电器、三路串口，再继续手写初始化代码，味道就不太对了。

可以把硬件资源做成配置表：

```
typedef struct
{
    GPIO_Registers_t *port;
    uint16_t pin;
    uint8_t active_level;
} GpioDeviceConfig_t;
```

定义 LED 配置。

```
static const GpioDeviceConfig_t g_led_config[] =
{
    {GPIOA, 1U << 0U, 1U},
    {GPIOA, 1U << 1U, 1U},
    {GPIOB, 1U << 5U, 0U},
    {GPIOB, 1U << 6U, 0U}
};
```

批量初始化。

```
#define ARRAY_SIZE(array) \
    (sizeof(array) / sizeof((array)[0]))

void led_init_all(void)
{
    uint32_t i;

    for (i = 0U; i < ARRAY_SIZE(g_led_config); i++)
    {
        gpio_output_init(g_led_config[i].port,
                         g_led_config[i].pin);
    }
}
```

统一控制接口也很好写。

```
void led_write(uint8_t index, uint8_t on)
{
    const GpioDeviceConfig_t *config;

    if (index >= ARRAY_SIZE(g_led_config))
    {
        return;
    }

    config = &g_led_config[index];

    if (on == config->active_level)
    {
        config->port->BSRR = config->pin;
    }
    else
    {
        config->port->BSRR = (uint32_t)config->pin << 16U;
    }
}
```

**在量产项目里**配置表的好处多多**。** 同一套软件适配不同硬件版本时，只要替换配置表，不需要满工程搜索 GPIO 编号。

```
#if defined(HARDWARE_V1)

static const GpioDeviceConfig_t g_relay_config[] =
{
    {GPIOA, 1U << 3U, 1U},
    {GPIOA, 1U << 4U, 1U}
};

#elif defined(HARDWARE_V2)

static const GpioDeviceConfig_t g_relay_config[] =
{
    {GPIOB, 1U << 8U, 0U},
    {GPIOB, 1U << 9U, 0U}
};

#endif
```

**硬件差异被锁在一张表里，业务代码不用跟着板子版本到处抽风。**

这个设计，有点东西。

### 9\. 中断事件结构体｜中断数据缓存、事件统一分发

**中断服务函数里最忌讳干重活。**

有人在串口中断里解析协议，在 ADC 中断里跑滤波算法，在定时器中断里打印日志。系统偶尔卡死后，还会怀疑是不是芯片不稳定。

芯片表示这锅我不背。

**中断里应该快速采集信息，再把事件交给主循环或任务处理。**

```
typedef enum
{
    EVENT_NONE = 0,
    EVENT_UART_RX,
    EVENT_ADC_READY,
    EVENT_TIMER_TIMEOUT,
    EVENT_GPIO_TRIGGER
} EventType_t;
```

定义统一事件。

```
typedef struct
{
    EventType_t type;
    uint32_t timestamp;

    union
    {
        struct
        {
            uint8_t port;
            uint8_t data;
        } uart;

        struct
        {
            uint8_t channel;
            uint16_t value;
        } adc;

        struct
        {
            uint8_t timer_id;
        } timer;

        struct
        {
            uint16_t pin;
            uint8_t level;
        } gpio;
    } data;
} InterruptEvent_t;
```

串口中断只负责创建事件。

```
void UART_IRQHandler(void)
{
    InterruptEvent_t event;

    if (uart_rx_ready())
    {
        event.type = EVENT_UART_RX;
        event.timestamp = system_tick_get();
        event.data.uart.port = 1U;
        event.data.uart.data = uart_read_byte();

        event_queue_push_from_isr(&event);
    }
}
```

主循环统一处理。

```
void event_process(void)
{
    InterruptEvent_t event;

    while (event_queue_pop(&event))
    {
        switch (event.type)
        {
            case EVENT_UART_RX:
                protocol_input_byte(event.data.uart.data);
                break;

            case EVENT_ADC_READY:
                adc_value_process(event.data.adc.channel,
                                  event.data.adc.value);
                break;

            case EVENT_TIMER_TIMEOUT:
                timer_event_process(event.data.timer.timer_id);
                break;

            case EVENT_GPIO_TRIGGER:
                gpio_event_process(event.data.gpio.pin,
                                   event.data.gpio.level);
                break;

            default:
                break;
        }
    }
}
```

中断快进快出。

复杂处理慢慢来。

系统稳定性会好很多，调试时也容易追踪事件来源。

### 10\. 引脚复用结构体｜多功能引脚资源统一管理

MCU 的一个引脚，可能既能做普通 GPIO，也能做 UART、SPI、I²C、定时器 PWM 或 ADC。

项目小的时候，哪里用到哪里配置。

项目一复杂，冲突就来了。

某个引脚刚被 UART 初始化，另一个模块又把它改成 PWM。两边代码都觉得自己没问题，板子却已经开始表演行为艺术。

可以定义引脚复用配置。

{

typedef struct

## 四、通信协议篇（4个）—— 串口/CAN/网络通用

### 11\. 定长协议帧结构体｜标准头尾校验、固定报文解析

固定长度协议是很多嵌入式设备的第一套通信协议。

假设一帧数据包含帧头、命令、长度、数据、校验和帧尾。

```
#define PROTOCOL_DATA_SIZE  8U

typedef struct
{
    uint16_t header;
    uint8_t command;
    uint8_t length;
    uint8_t data[PROTOCOL_DATA_SIZE];
    uint16_t checksum;
    uint16_t tail;
} FixedFrame_t;
```

构造一帧数据。

```
void frame_build(FixedFrame_t *frame,
                 uint8_t command,
                 const uint8_t *data,
                 uint8_t length)
{
    uint8_t i;

    if ((frame == NULL) || (data == NULL))
    {
        return;
    }

    if (length > PROTOCOL_DATA_SIZE)
    {
        length = PROTOCOL_DATA_SIZE;
    }

    frame->header = 0xAA55U;
    frame->command = command;
    frame->length = length;

    for (i = 0U; i < PROTOCOL_DATA_SIZE; i++)
    {
        frame->data[i] = 0U;
    }

    for (i = 0U; i < length; i++)
    {
        frame->data[i] = data[i];
    }

    frame->checksum = frame_checksum(frame);
    frame->tail = 0x0D0AU;
}
```

解析时不要一收到数据就直接强转指针。

```
FixedFrame_t *frame = (FixedFrame_t *)rx_buffer;
```

**这种写法看着省事，却可能遇到结构体填充、地址未对齐、字节序和非法长度问题。**

更稳妥的做法是逐字段解析。

```
bool frame_parse(const uint8_t *buffer,
                 uint16_t size,
                 FixedFrame_t *frame)
{
    if ((buffer == NULL) || (frame == NULL))
    {
        return false;
    }

    if (size != 16U)
    {
        return false;
    }

    frame->header = ((uint16_t)buffer[0] << 8U)
                  | ((uint16_t)buffer[1]);

    frame->command = buffer[2];
    frame->length = buffer[3];

    memcpy(frame->data, &buffer[4], PROTOCOL_DATA_SIZE);

    frame->checksum = ((uint16_t)buffer[12] << 8U)
                    | ((uint16_t)buffer[13]);

    frame->tail = ((uint16_t)buffer[14] << 8U)
                | ((uint16_t)buffer[15]);

    if (frame->header != 0xAA55U)
    {
        return false;
    }

    if (frame->tail != 0x0D0AU)
    {
        return false;
    }

    return frame_checksum(frame) == frame->checksum;
}
```

**协议结构体是内存中的逻辑模型，线上的字节流是传输格式。** 这两者长得像，不代表永远可以直接画等号。很多通信 Bug 都是从"我直接强转一下应该没事吧"开始的。

### 12\. 紧凑对齐结构体｜消除内存填充、适配二进制透传

编译器为了提高访问效率，会在结构体成员之间插入填充字节。

看下面这个结构体。

```
typedef struct
{
    uint8_t type;
    uint32_t timestamp;
    uint16_t value;
} Sample_t;
```

字段大小加起来是 7 字节。

结构体实际大小却可能是 12 字节。

```
printf("%u\n", (unsigned int)sizeof(Sample_t));
```

原因并不神秘。`uint32_t` 往往需要按 4 字节对齐，编译器会在 `type` 后面补空位，结构体末尾也可能继续补齐。

需要和二进制协议严格对应时，可以使用紧凑对齐。

GCC 常见写法如下。

```
typedef struct __attribute__((packed))
{
    uint8_t type;
    uint32_t timestamp;
    uint16_t value;
} PackedSample_t;
```

部分编译器也支持下面的形式。

```
#pragma pack(push, 1)

typedef struct
{
    uint8_t type;
    uint32_t timestamp;
    uint16_t value;
} PackedSample_t;

#pragma pack(pop)
```

**紧凑结构体不是免费午餐。** 未对齐的 `uint32_t` 在某些 MCU 上访问速度会下降，严重时还可能触发硬件异常。

因此，**别因为看到 `packed` 很酷，就给全项目结构体都套上。**

协议层可以紧凑。

CPU 内部频繁访问的数据结构，尽量保持自然对齐。

还有一种办法更朴素，**手动调整字段顺序。**

```
typedef struct
{
    uint32_t timestamp;
    uint16_t value;
    uint8_t type;
    uint8_t reserved;
} AlignedSample_t;
```

合理排序后，内存利用率可能已经足够好，同时保留正常访问性能。

### 13\. 柔性数组结构体｜变长报文、无碎片内存分配

通信帧长度不固定时，可以使用柔性数组成员。

柔性数组必须放在结构体最后，而且不指定长度。

```
typedef struct
{
    uint16_t command;
    uint16_t length;
    uint8_t payload[];
} VariableFrame_t;
```

分配一段连续内存。

```
VariableFrame_t *frame_create(uint16_t command,
                              uint16_t payload_length)
{
    VariableFrame_t *frame;
    size_t total_size;

    total_size = sizeof(VariableFrame_t) + payload_length;

    frame = malloc(total_size);

    if (frame == NULL)
    {
        return NULL;
    }

    frame->command = command;
    frame->length = payload_length;

    memset(frame->payload, 0, payload_length);

    return frame;
}
```

使用时，头部和数据区在同一块内存里。

```
VariableFrame_t *frame;

frame = frame_create(0x1001U, 32U);

if (frame != NULL)
{
    frame->payload[0] = 0x11U;
    frame->payload[1] = 0x22U;

    protocol_send((uint8_t *)frame,
                  sizeof(VariableFrame_t) + frame->length);

    free(frame);
}
```

在裸机系统里，我一般不太喜欢频繁 `malloc` 和 `free`。不是内存分配不能用，而是长时间运行后，内存碎片和分配失败会很难排查。

更稳的方式是从固定内存池里申请。

```
#define FRAME_BUFFER_SIZE  128U

typedef union
{
    uint8_t raw[FRAME_BUFFER_SIZE];

    struct
    {
        uint16_t command;
        uint16_t length;
        uint8_t payload[FRAME_BUFFER_SIZE - 4U];
    } frame;
} FrameBuffer_t;
```

**柔性数组最适合 Linux、RTOS 动态消息和一次性组包。**

资源特别紧张的小 MCU，可以借它的设计思想，但不一定非要跟动态内存绑死。

### 14\. 序列化结构体｜大小端适配、跨设备数据交互

两个设备通信时，最容易被忽略的问题之一就是字节序。

数值 `0x12345678` 在大端格式里按下面的顺序发送：

```
12 34 56 78
```

在小端内存里，顺序通常是下面这样：

```
78 56 34 12
```

如果把结构体直接 `memcpy` 到串口，不同架构之间可能立即翻车。

定义业务结构体没有问题。

```
typedef struct
{
    uint32_t device_id;
    int16_t temperature;
    uint16_t voltage;
    float current;
} Telemetry_t;
```

但序列化时，要明确每个字段如何转换。

```
static void write_u16_be(uint8_t *buffer, uint16_t value)
{
    buffer[0] = (uint8_t)(value >> 8U);
    buffer[1] = (uint8_t)value;
}

static void write_u32_be(uint8_t *buffer, uint32_t value)
{
    buffer[0] = (uint8_t)(value >> 24U);
    buffer[1] = (uint8_t)(value >> 16U);
    buffer[2] = (uint8_t)(value >> 8U);
    buffer[3] = (uint8_t)value;
}
```

序列化函数把结构体转成稳定的线格式。

```
uint16_t telemetry_serialize(const Telemetry_t *telemetry,
                             uint8_t *buffer,
                             uint16_t buffer_size)
{
    Data32_t current_data;

    if ((telemetry == NULL) || (buffer == NULL))
    {
        return 0U;
    }

    if (buffer_size < 12U)
    {
        return 0U;
    }

    write_u32_be(&buffer[0], telemetry->device_id);
    write_u16_be(&buffer[4], (uint16_t)telemetry->temperature);
    write_u16_be(&buffer[6], telemetry->voltage);

    current_data.f32 = telemetry->current;

    buffer[8]  = current_data.bytes[3];
    buffer[9]  = current_data.bytes[2];
    buffer[10] = current_data.bytes[1];
    buffer[11] = current_data.bytes[0];

    return 12U;
}
```

更严谨的系统会对浮点格式也作出协议约束，或者干脆把浮点量放大后转成整数。

比如温度 25.37℃，传输 `2537`。

```
int16_t temperature_x100;
```

比直接传浮点更可控，也方便跨语言、跨平台解析。

### 15\. 掉电参数存储结构体｜PID/校准值/用户参数持久化

设备断电后还要保留的参数，通常会存进内部 Flash、外部 EEPROM 或 FRAM。

**不要看到一个参数就单独写一次 Flash。**

把一组参数统一做成存储结构体，版本管理和校验都会方便很多。

```
typedef struct
{
    float kp;
    float ki;
    float kd;

    float sensor_gain;
    float sensor_offset;

    uint16_t device_address;
    uint8_t work_mode;
    uint8_t language;
} PersistentParam_t;
```

RAM 中保留一个工作副本。

```
static PersistentParam_t g_param;
```

加载流程通常包括读取、校验和恢复默认值。

```
void parameter_load(void)
{
    if (storage_read((uint8_t *)&g_param,
                     sizeof(g_param)) == false)
    {
        parameter_set_default(&g_param);
        return;
    }

    if (parameter_is_valid(&g_param) == false)
    {
        parameter_set_default(&g_param);
    }
}
```

默认参数集中设置。

```
void parameter_set_default(PersistentParam_t *param)
{
    memset(param, 0, sizeof(*param));

    param->kp = 1.0f;
    param->ki = 0.1f;
    param->kd = 0.01f;

    param->sensor_gain = 1.0f;
    param->sensor_offset = 0.0f;

    param->device_address = 1U;
    param->work_mode = 0U;
    param->language = 0U;
}
```

**实际项目里还要考虑 Flash 擦写次数。**

用户在界面上拖一下滑块，别立刻写 Flash。可以设置脏标记，延迟一段时间批量保存。

```
typedef struct
{
    PersistentParam_t value;

    uint8_t dirty;
    uint32_t changed_tick;
} ParameterManager_t;

void parameter_mark_changed(ParameterManager_t *manager)
{
    manager->dirty = 1U;
    manager->changed_tick = system_tick_get();
}
```

主循环检测参数稳定后再写。

```
void parameter_save_process(ParameterManager_t *manager)
{
    uint32_t now;

    if (manager->dirty == 0U)
    {
        return;
    }

    now = system_tick_get();

    if ((now - manager->changed_tick) < 2000U)
    {
        return;
    }

    storage_write((const uint8_t *)&manager->value,
                  sizeof(manager->value));

    manager->dirty = 0U;
}
```

写着写着，寿命就写没了。

### 16\. CRC校验防护结构体｜防止存储数据损坏丢失

只把参数写进 Flash 还不够。

掉电瞬间、电磁干扰、写入中断和 Flash 老化，都可能让数据损坏。设备下次开机读到错误参数，轻则显示异常，重则电机直接冲出去。

给存储结构体增加魔数、版本、长度和 CRC。

```
typedef struct
{
    uint32_t magic;
    uint16_t version;
    uint16_t length;

    PersistentParam_t param;

    uint32_t crc32;
} ParameterStorage_t;
```

保存时先计算 CRC。

```
#define PARAMETER_MAGIC  0x50415241UL
#define PARAMETER_VERSION  2U

bool parameter_storage_save(const PersistentParam_t *param)
{
    ParameterStorage_t storage;

    memset(&storage, 0, sizeof(storage));

    storage.magic = PARAMETER_MAGIC;
    storage.version = PARAMETER_VERSION;
    storage.length = sizeof(PersistentParam_t);
    storage.param = *param;

    storage.crc32 = crc32_calculate(
        (const uint8_t *)&storage,
        offsetof(ParameterStorage_t, crc32));

    return flash_write(PARAMETER_FLASH_ADDRESS,
                       (const uint8_t *)&storage,
                       sizeof(storage));
}
```

读取时逐项检查。

```
bool parameter_storage_load(PersistentParam_t *param)
{
    ParameterStorage_t storage;
    uint32_t calculated_crc;

    if (flash_read(PARAMETER_FLASH_ADDRESS,
                   (uint8_t *)&storage,
                   sizeof(storage)) == false)
    {
        return false;
    }

    if (storage.magic != PARAMETER_MAGIC)
    {
        return false;
    }

    if (storage.version != PARAMETER_VERSION)
    {
        return false;
    }

    if (storage.length != sizeof(PersistentParam_t))
    {
        return false;
    }

    calculated_crc = crc32_calculate(
        (const uint8_t *)&storage,
        offsetof(ParameterStorage_t, crc32));

    if (calculated_crc != storage.crc32)
    {
        return false;
    }

    *param = storage.param;

    return true;
}
```

我曾经看过一套设备，存储参数没有 CRC，也没有版本号。

早期版本保存 32 字节，后来的固件把结构体扩成了 48 字节。升级后继续按照新格式读取旧数据，后半截全是随机值。

现场出现过一个特别离谱的问题：设备升级后，菜单语言随机变化，报警阈值偶尔变成负数。有人怀疑 EEPROM 芯片批次不行，折腾半个月。

后来一看，存储格式裸奔呢。

## 六、架构OOP篇（3个）—— 大厂工程分层思想

### 18\. 函数指针Ops结构体｜C语言模拟面向对象

C 语言没有类，也没有虚函数。

但函数指针结构体可以实现统一接口。

假设系统支持 UART、USB 和 CAN 三种通信通道，上层只想调用发送和接收，不想知道底层是谁。

```
typedef struct
{
    int32_t (*open)(void *context);
    int32_t (*close)(void *context);

    int32_t (*write)(void *context,
                     const uint8_t *data,
                     uint32_t length);

    int32_t (*read)(void *context,
                    uint8_t *data,
                    uint32_t length);
} CommunicationOps_t;
```

UART 实现一套函数。

```
static int32_t uart_open(void *context)
{
    UartContext_t *uart = context;

    return uart_hardware_init(uart->instance,
                              uart->baudrate);
}

static int32_t uart_write(void *context,
                          const uint8_t *data,
                          uint32_t length)
{
    UartContext_t *uart = context;

    return uart_hardware_send(uart->instance,
                              data,
                              length);
}
```

把函数装进接口表。

```
static const CommunicationOps_t g_uart_ops =
{
    .open = uart_open,
    .close = uart_close,
    .write = uart_write,
    .read = uart_read
};
```

USB、CAN 也各自实现一套。

上层只认 `CommunicationOps_t`。

```
typedef struct
{
    const CommunicationOps_t *ops;
    void *context;
} CommunicationDevice_t;
```

调用代码完全统一。

```
int32_t communication_send(CommunicationDevice_t *device,
                           const uint8_t *data,
                           uint32_t length)
{
    if ((device == NULL) ||
        (device->ops == NULL) ||
        (device->ops->write == NULL))
    {
        return -1;
    }

    return device->ops->write(device->context,
                              data,
                              length);
}
```

### 19\. 设备对象结构体｜私有数据+操作接口封装

### 20\. 回调钩子结构体｜软硬件解耦、异步事件处理

    uint8_t stop_request;

        return;

    machine->current = new_state;
    machine->state_enter_tick = system_tick_get();

static void state_running(MachineState_t *machine)

    if (machine->fault_detected)

        return;
    }

    if (machine->stop_request)
    {
        machine_change_state(machine, STATE_STOPPING);

void machine_process(MachineState_t *machine)

    if (handler != NULL)

        handler(machine);
    }

### 23\. 单向/双向链表节点结构体｜通用设备管理

链表的核心，就是在结构体里保存指向其他节点的指针。

单向链表节点如下。

```
typedef struct DeviceNode

添加节点。

void device_list_add(DeviceNode_t **head,
                     DeviceNode_t *node)
{
    if ((head == NULL) || (node == NULL))

        return;
    }

    node->next = *head;
    *head = node;

遍历设备。

void device_list_print(DeviceNode_t *head)

typedef struct ListNode
{
    struct ListNode *previous;

### 24\. 环形队列结构体｜中断缓存、数据异步缓冲

**环形队列是嵌入式里最实用的数据结构之一。**

串口中断收数据、ADC 采样缓存、日志输出、任务间通信，全能用。

```
#define RING_BUFFER_SIZE  128U

typedef struct
{
    uint8_t buffer[RING_BUFFER_SIZE];

    volatile uint16_t head;
    volatile uint16_t tail;

    uint16_t capacity;
} RingBuffer_t;
```

初始化。

```
void ring_buffer_init(RingBuffer_t *ring)
{
    ring->head = 0U;
    ring->tail = 0U;
    ring->capacity = RING_BUFFER_SIZE;
}
```

判断是否为空。

```
bool ring_buffer_is_empty(const RingBuffer_t *ring)
{
    return ring->head == ring->tail;
}
```

判断是否已满。

```
bool ring_buffer_is_full(const RingBuffer_t *ring)
{
    uint16_t next;

    next = (uint16_t)((ring->head + 1U) % ring->capacity);

    return next == ring->tail;
}
```

写入一个字节。

```
bool ring_buffer_push(RingBuffer_t *ring,
                      uint8_t data)
{
    uint16_t next;

    next = (uint16_t)((ring->head + 1U) % ring->capacity);

    if (next == ring->tail)
    {
        return false;
    }

    ring->buffer[ring->head] = data;
    ring->head = next;

    return true;
}
```

读取一个字节。

```
bool ring_buffer_pop(RingBuffer_t *ring,
                     uint8_t *data)
{
    if ((ring == NULL) || (data == NULL))
    {
        return false;
    }

    if (ring->head == ring->tail)
    {
        return false;
    }

    *data = ring->buffer[ring->tail];

    ring->tail =
        (uint16_t)((ring->tail + 1U) % ring->capacity);

    return true;
}
```

有一个槽位会被用来区分队列满和队列空，因此实际可用容量通常是 `capacity - 1`。

也可以额外保存元素数量，但中断和主线程同时访问时，要考虑原子性。

```
typedef struct
{
    uint8_t *buffer;

    uint16_t capacity;
    volatile uint16_t head;
    volatile uint16_t tail;
    volatile uint16_t count;
} GenericRingBuffer_t;
```

单生产者、单消费者模型下，合理设计后可以减少加锁。

**多个任务同时读写，就别凭感觉认为它线程安全。该加锁加锁，该关中断关中断。**

### 25\. 树形层级结构体｜多级设备、模块层级管理

有些设备天然具有层级关系。

整机下面有控制板，控制板下面有模块，模块下面还有通道。

把所有对象平铺到数组里，会很难表达父子关系。

可以使用树形节点。

```
typedef enum
{
    NODE_TYPE_SYSTEM,
    NODE_TYPE_BOARD,
    NODE_TYPE_MODULE,
    NODE_TYPE_CHANNEL
} NodeType_t;

typedef struct TreeNode
{
    const char *name;
    NodeType_t type;

    void *data;

    struct TreeNode *parent;
    struct TreeNode *first_child;
    struct TreeNode *next_sibling;
} TreeNode_t;
```

添加子节点。

```
void tree_add_child(TreeNode_t *parent,
                    TreeNode_t *child)
{
    TreeNode_t *node;

    if ((parent == NULL) || (child == NULL))
    {
        return;
    }

    child->parent = parent;
    child->next_sibling = NULL;

    if (parent->first_child == NULL)
    {
        parent->first_child = child;
        return;
    }

    node = parent->first_child;

    while (node->next_sibling != NULL)
    {
        node = node->next_sibling;
    }

    node->next_sibling = child;
}
```

递归遍历。

```
void tree_visit(TreeNode_t *node,
                uint8_t depth)
{
    TreeNode_t *child;
    uint8_t i;

    if (node == NULL)
    {
        return;
    }

    for (i = 0U; i < depth; i++)
    {
        printf("  ");
    }

    printf("%s\n", node->name);

    child = node->first_child;

    while (child != NULL)
    {
        tree_visit(child, depth + 1U);
        child = child->next_sibling;
    }
}
```

这种结构很适合设备管理、GUI 控件树、菜单系统、文件系统和组合式传感器。

节点内保存 `void *data`，可以挂接不同类型的私有对象。

树形结构不一定要动态分配。资源固定的系统，完全可以用静态节点提前搭建。

**嵌入式不是见到指针就必须 `malloc`，别被桌面开发的习惯带偏了。**

### 26\. RTOS资源绑定结构体｜锁/信号量+外设线程安全

裸机项目里，一个串口通常只有一个执行流访问。

上了 RTOS 后，日志任务要发数据，协议任务也要发数据，升级任务还想发数据。大家同时操作同一个外设，不加保护，输出内容就会互相穿插。

把资源锁和设备对象绑定起来。

```
typedef struct
{
    Device_t *device;

    MutexHandle_t mutex;
    SemaphoreHandle_t tx_complete;
    SemaphoreHandle_t rx_ready;

    uint8_t initialized;
} RtosDevice_t;
```

线程安全发送函数如下。

```
int32_t rtos_device_write(RtosDevice_t *rtos_device,
                          const uint8_t *data,
                          uint32_t length,
                          uint32_t timeout)
{
    int32_t result;

    if ((rtos_device == NULL) ||
        (rtos_device->device == NULL))
    {
        return -1;
    }

    if (mutex_lock(rtos_device->mutex, timeout) == false)
    {
        return -2;
    }

    result = device_write(rtos_device->device,
                          data,
                          length);

    if (result == 0)
    {
        if (semaphore_take(rtos_device->tx_complete,
                           timeout) == false)
        {
            result = -3;
        }
    }

    mutex_unlock(rtos_device->mutex);

    return result;
}
```

DMA 发送完成中断释放信号量。

```
void uart_dma_tx_complete_isr(RtosDevice_t *device)
{
    bool need_schedule = false;

    semaphore_give_from_isr(device->tx_complete,
                            &need_schedule);

    rtos_yield_from_isr(need_schedule);
}
```

结构体把硬件对象、互斥锁和完成信号绑定在一起后，资源归属会非常清楚。

更进一步，还可以加入拥有者、超时统计和错误计数。

```
typedef struct
{
    Device_t *device;

    MutexHandle_t mutex;
    SemaphoreHandle_t completion;

    uint32_t lock_timeout_count;
    uint32_t transfer_timeout_count;
    uint32_t error_count;

    const char *owner_name;
} ProtectedDevice_t;
```

这类统计字段很有用。系统偶发卡顿时，可以直接看锁超时次数。

} Widget_t;
```

判断触摸点是否落在控件内。

```
bool widget_contains_point(const Widget_t *widget,
                           int16_t x,
                           int16_t y)
{
    if ((widget == NULL) ||
        (widget->state.visible == 0U) ||
        (widget->state.enabled == 0U))
    {
        return false;
    }

    return (x >= widget->bounds.x) &&
           (y >= widget->bounds.y) &&
           (x < widget->bounds.x + widget->bounds.width) &&
           (y < widget->bounds.y + widget->bounds.height);
}
```

按钮可以在控件基础上增加自己的数据。

```
typedef struct
{
    Widget_t base;

    const char *text;
    uint16_t normal_color;
    uint16_t pressed_color;

    void (*on_click)(void *user_data);
} Button_t;
```

这里有一点类似继承。

把 `Widget_t base` 放在第一个成员，`Button_t *` 转成 `Widget_t *` 时地址保持一致。

```
Button_t button;

Widget_t *widget = (Widget_t *)&button;
```

不少 C 语言 GUI 框架都会采用类似设计。

坐标结构体看起来简单，真正进入产品后还要面对父子坐标转换、裁剪区域、透明度、触摸捕获和重绘脏区。

但根基仍然是结构体——控件是什么，在哪，能干什么，都得有地方存。

### 28\. 运动轨迹结构体｜电机点位、运动插值数据存储

机器人、电机控制、数控设备和云台系统里，运动轨迹不能只用一个目标位置表示。

一个点通常还包含速度、加速度、时间和插值类型。

```
typedef struct
{
    float position;
    float velocity;
    float acceleration;

    uint32_t time_ms;
} MotionPoint_t;
```

多轴运动可以继续组合。

```
typedef struct
{
    float x;
    float y;
    float z;

    float roll;
    float pitch;
    float yaw;
} RobotPose_t;

typedef struct
{
    RobotPose_t pose;

    float linear_velocity;
    float angular_velocity;
    float acceleration;

    uint32_t duration_ms;
} TrajectoryPoint_t;
```

一条轨迹由多个点组成。

```
#define TRAJECTORY_MAX_POINTS  64U

typedef enum
{
    INTERPOLATION_LINEAR,
    INTERPOLATION_CUBIC,
    INTERPOLATION_QUINTIC
} InterpolationType_t;

typedef struct
{
    TrajectoryPoint_t points[TRAJECTORY_MAX_POINTS];

    uint16_t point_count;
    uint16_t current_index;

    InterpolationType_t interpolation;

    uint32_t start_tick;
    uint8_t running;
    uint8_t paused;
    uint8_t completed;
} Trajectory_t;
```

添加轨迹点。

```
bool trajectory_add_point(Trajectory_t *trajectory,
                          const TrajectoryPoint_t *point)
{
    if ((trajectory == NULL) || (point == NULL))
    {
        return false;
    }

    if (trajectory->point_count >= TRAJECTORY_MAX_POINTS)
    {
        return false;
    }

    trajectory->points[trajectory->point_count] = *point;
    trajectory->point_count++;

    return true;
}
```

运行时根据当前时间计算插值位置。

```
float linear_interpolate(float start,
                         float end,
                         float ratio)
{
    if (ratio < 0.0f)
    {
        ratio = 0.0f;
    }

    if (ratio > 1.0f)
    {
        ratio = 1.0f;
    }

    return start + (end - start) * ratio;
}
```

三次或五次插值还需要保存边界速度和加速度。

```
typedef struct
{
    float start_position;
    float end_position;

    float start_velocity;
    float end_velocity;

    float start_acceleration;
    float end_acceleration;

    float duration;
} QuinticBoundary_t;
```

规划器计算出多项式系数后，可以继续放进结构体。

```
typedef struct
{
    float a0;
    float a1;
    float a2;
    float a3;
    float a4;
    float a5;

    float duration;
} QuinticPolynomial_t;
```

计算某一时刻的位置。

```
float quintic_position(const QuinticPolynomial_t *poly,
                       float time)
{
    float t2;
    float t3;
    float t4;
    float t5;

    if (time < 0.0f)
    {
        time = 0.0f;
    }

    if (time > poly->duration)
    {
        time = poly->duration;
    }

    t2 = time * time;
    t3 = t2 * time;
    t4 = t3 * time;
    t5 = t4 * time;

    return poly->a0
         + poly->a1 * time
         + poly->a2 * t2
         + poly->a3 * t3
         + poly->a4 * t4
         + poly->a5 * t5;
}
```

**运动控制对结构体设计要求很高。**

规划层要保存目标。

插值层要保存系数。

执行层要保存当前点位。

故障层还要保存跟随误差、限位状态和急停信息。

全靠零散变量堆着，迟早会乱。

**把轨迹定义清楚，控制算法才有稳定的数据边界。**

## 写在后面

这 28 个结构体，并不是 28 套互不相关的语法模板。

**它们会在真实项目里不断组合。**

一个带远程升级功能的电机控制器，可能同时包含设备对象、操作接口、RTOS 资源锁、状态机、故障日志、存储参数、Bootloader 分区和运动轨迹。

看起来复杂吗？确实复杂。

可一旦每一类数据都找到自己的结构体，系统就不会再像一间堆满杂物的仓库。驱动归驱动，状态归状态，配置归配置，协议归协议。

**结构体设计真正厉害的地方，不是少写几行代码。**

**它决定了一个项目半年以后还能不能改，换个人接手后会不会骂街，设备量产几万台后出现问题时还能不能追得回来。**

我现在看嵌入式代码，通常不会先看算法写得多漂亮。

我会先找几个东西：

**设备对象怎么定义，状态放在哪里，参数怎么保存，错误怎么记录，硬件资源有没有统一管理。**

这些结构体要是设计得靠谱，项目通常不会差到哪去。

要是所有数据都躺在全局变量里，还配着几十个 `flag1`、`flag2`、`temp_data` 和 `test_value`，那就做好心理准备吧。

代码暂时没炸，只是时候未到。
