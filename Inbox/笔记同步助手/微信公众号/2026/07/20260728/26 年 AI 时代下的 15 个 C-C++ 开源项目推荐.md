大家好，我是蟹老板～

以前我们学习 C/C++，练习方向大多是服务器开发、嵌入式、音视频、游戏引擎。 但进入AI爆发的时代，C/C++最重要的战场已经转移到：**AI推理、模型编译、算子优化、端侧部署、高性能数值计算**。

今天给大家分享一些在 26 年 AI 时代，非常优质的 C/C++ 项目。

选这些项目的核心原则就是**不烂大街、而且一定技术门槛、贴合 AI 基础设施发展趋势。**

> 这里需要提前说明一点：项目并不是整个仓库都使用 C/C++。

> 比如它们用 Python 提供前端接口，但真正涉及计算图、运行时、内存管理、算子调度和 GPU Kernel 的关键性能路径，仍然大量依赖 C++、CUDA 或底层编译器技术。

所以这篇文章所说的“C/C++ 项目”，指的是：

> **C/C++ 主导底层架构或关键性能路径的 AI 基础设施项目。**

## 一、15个值得深度拆解的C/C++开源项目

### 1.1 llama.cpp

llama.cpp 是推动本地大模型普及的标杆项目，采用纯C实现，主打轻量化大模型推理，实现GGUF模型格式，支持CPU、移动端、嵌入式无GPU环境运行LLM。

![[Inbox/笔记同步助手/微信公众号/2026/07/images/3b3b442544077edf5397fd9a01c4fe39_MD5.jpg]]

```
GitHub地址：https://github.com/ggerganov/llama.cpp
```

> 开源协议：MIT
> 
> GitHub星标：121.8k+
> 
> 复刻建议：复刻GGUF模型加载、量化解码、KV缓存、基础token生成闭环

**功能特性：**

-   • 纯C编写，无强制依赖，跨平台移植门槛极低
    
-   • 支持4bit/8bit等多种模型量化方案
    
-   • GGUF模型存储格式，替代老旧GGML
    
-   • CPU高效推理，支持AVX2、NEON硬件指令加速
    
-   • KV缓存复用、连续批处理提升并发能力
    
-   • 支持LLaMA、Qwen、Mistral、Phi等主流大模型
    
-   • 适配PC、安卓、树莓派、各类嵌入式开发板
    

**复刻能学到啥：** 很多新手调用大模型只会调用现成API，完全不清楚文本生成底层流程。

```
// 普通使用者视角
send_prompt("请简单介绍C语言");
get_response();
```

看似简单，背后包含模型读取、权重反量化、矩阵运算、token自回归生成整套流程。

llama.cpp最大价值，是把**大模型CPU推理完整链路摊开**。 核心思路简化理解：

```
加载量化权重 → 反量化恢复浮点数据 → Transformer前向计算 → KV缓存迭代复用 → 逐token采样输出文本
```

市面上很多教程只讲理论Transformer，缺少可运行极简工程。llama.cpp用极简C代码实现推理，非常适合理解大模型推理底层，搞懂量化、KV缓存、采样策略这些高频面试重点。

**复刻目标：** 无需实现完整Transformer，搭建最小验证框架：

-   • 实现GGUF文件解析、权重读取
    
-   • 实现矩阵向量乘量化运算
    
-   • 简易KV缓存结构设计
    
-   • 搭建极简自回归token生成流程
    

### 1.2 TensorRT-LLM

TensorRT-LLM 是英伟达推出、面向GPU的大模型推理加速库，基于TensorRT构建，专门优化LLM在NVIDIA显卡上的高吞吐、低延迟部署。

![[Inbox/笔记同步助手/微信公众号/2026/07/images/4d41b2332d5d6a9f4cc42f6515459f02_MD5.jpg]]

```
GitHub地址：https://github.com/NVIDIA/TensorRT-LLM
```

> 开源协议：Apache-2.0
> 
> GitHub星标：14.2k+
> 
> 复刻建议：复刻PagedAttention、KV缓存管理、批调度核心逻辑

**功能特性：**

-   • 针对NVIDIA GPU深度优化算子
    
-   • 实现PagedAttention分页注意力，大幅降低显存占用
    
-   • 支持连续批处理、动态批处理
    
-   • 支持FP16、INT4、INT8量化推理
    
-   • 兼容主流开源大模型，支持分布式推理
    
-   • 面向云端大模型服务场景，追求高并发吞吐
    

**复刻能学到啥：** 很多人搭建LLM服务只会直接部署现成框架，遇到显存溢出、QPS上不去无从优化。 云端推理最大瓶颈往往不是算力，而是**KV缓存显存浪费**。

TensorRT-LLM最核心创新就是PagedAttention，借鉴操作系统虚拟内存分页思想管理KV缓存。 传统方案：为每个请求预分配整块连续显存 PagedAttention：使用离散分页块，按需分配、复用内存，极大提升并发上限。

这套内存管理思想，不仅用于LLM推理，在高性能服务、缓冲区设计都具备参考价值。

**复刻目标：**

-   • 模拟分页式KV缓存数据结构
    
-   • 实现请求调度、缓存块分配回收逻辑
    
-   • 理解批推理请求生命周期管理
    

### 1.3 ONNX Runtime

ONNX Runtime（ORT）是微软开源跨平台推理引擎，支持ONNX通用模型格式，打通训练框架与部署环境，CPU/GPU/NPU多硬件统一运行。

![[Inbox/笔记同步助手/微信公众号/2026/07/images/17728e497b139c6e599d9a4f16eb1f68_MD5.jpg]]

```
GitHub地址：https://github.com/microsoft/onnxruntime
```

> 开源协议：MIT
> 
> GitHub星标：21.2k+
> 
> 复刻建议：复刻算子注册、计算图解析、基础算子执行闭环

**功能特性：**

-   • 统一支持ONNX标准模型文件
    
-   • 多执行提供者：CPU、CUDA、TensorRT、OpenVINO等
    
-   • 支持图优化、算子融合、常量折叠
    
-   • 动态shape推理，适配图像、NLP各类模型
    
-   • C/C++核心底层，对外提供多语言绑定
    
-   • 广泛用于桌面、服务端、移动端AI部署
    

**复刻能学到啥：** 很多工程师只知道导出ONNX模型，不明白推理引擎如何解析、运行计算图。

```
# 表层操作
model = onnx.load("model.onnx")
session.run(inputs)
```

底层本质：序列化模型解析 → 计算图优化 → 算子调度执行 → 张量内存管理。

ONNX Runtime展示了一套标准推理引擎架构：**计算图抽象 + 算子注册机制 + 多硬件后端抽象**。 这套分层思想，是所有推理框架通用范式。

**复刻目标：**

-   • 实现简易ONNX proto模型解析
    
-   • 设计张量Tensor内存结构
    
-   • 搭建算子注册表，实现Conv、Matmul基础算子调度
    
-   • 实现简单算子融合优化
    

### 1.4 Apache TVM

Apache TVM 面向深度学习的端到端编译器栈，目标让模型高效运行在各类异构硬件CPU/GPU/NPU/MCU，解决模型跨硬件优化难题。

![[Inbox/笔记同步助手/微信公众号/2026/07/images/5dd6bea491911e0de26033b0d96d2313_MD5.jpg]]

```
GitHub地址：https://github.com/apache/tvm
```

> 开源协议：Apache-2.0
> 
> GitHub星标：13.6k+
> 
> 复刻建议：复刻计算图IR、算子调度、目标代码生成极简链路

**功能特性：**

-   • 多层中间表示：Relay高层IR、TIR底层算子IR
    
-   • 自动算子优化、循环变换、向量化、并行调度
    
-   • 支持编译生成C、CUDA、Hexagon、RISC-V代码
    
-   • 对接各类训练框架，编译模型到异构硬件
    
-   • 兼顾云端GPU与嵌入式端侧场景
    

**复刻能学到啥：** 单纯调用推理引擎只能完成部署；TVM带你理解**AI算子如何自动优化**。 传统开发：手写CUDA/汇编算子，适配成本极高。 TVM思路：用抽象IR描述计算，通过调度原语自动变换循环结构，面向不同硬件生成最优代码。

这是AI编译器最核心思想，也是当下芯片、AI基础设施领域紧缺技能。

**复刻目标：**

-   • 搭建简易计算图中间表示
    
-   • 实现基础循环优化变换
    
-   • 实现IR向下生成C代码的最简流程
    

### 1.5 MLIR

MLIR（Multi-Level Intermediate Representation）是谷歌开源多层中间表示框架，不属于推理引擎，是构建编译器的基础设施，广泛用于TVM、TensorFlow、LLVM生态。


> 开源协议：Apache-2.0
> 
> 复刻建议：复刻基础IR节点、属性、操作定义、遍历机制

**功能特性：**

-   • 支持多层级自定义方言(Dialect)
    
-   • 通用IR基础设施，提供标准化遍历、重写工具
    
-   • 无缝对接LLVM，可生成机器码
    
-   • 大量AI编译器、硬件编译器基于MLIR二次开发
    
-   • 适合构建面向深度学习、异构硬件的编译栈
    

**复刻能学到啥：** MLIR学习门槛偏高，但收益极高。当下新一代NPU编译器、模型优化工具大量基于MLIR开发。 核心思想：**可扩展分层IR，不同层级做不同优化**。高层处理模型图，底层处理硬件指令。

看懂MLIR，就能看懂现代编译器通用设计范式，跳出单纯应用开发视角。

**复刻目标：**

-   • 实现简易IR节点与操作定义
    
-   • 编写IR遍历、模式匹配重写工具
    
-   • 理解方言(Dialect)扩展机制

**复刻能学到啥：** 大模型应用时代，RAG成为标配，向量检索是核心底座。 很多开发者只会调用API，不懂HNSW、IVF索引原理。 Faiss展示如何平衡检索速度、内存占用、召回精度，掌握高维向量算法底层实现。

**复刻目标：**

-   • 实现欧式距离、内积计算
    
-   • 搭建简易HNSW近邻搜索图结构
    
-   • 实现小规模向量库检索逻辑

## 二、推荐复刻学习顺序

如果你不知道从哪一个开始，可以按这个顺序来：

| 阶段 | 项目 | 核心收获 |
| :-- | :-- | :-- |
| 入门 | OpenBLAS | 矩阵乘法优化、缓存分块、SIMD |
| 入门 | FreeRTOS | 任务调度、链表、嵌入式基础 |
| 入门 | ncnn | 端侧推理、层抽象、ARM 优化 |
| 进阶 | ggml | 张量库设计、量化、计算图 |
| 进阶 | llama.cpp | LLM 推理、KV Cache、Transformer |
| 进阶 | ONNX Runtime | 执行提供者、跨平台抽象 |
| 进阶 | Faiss | 向量索引、近似搜索、量化 |
| 深入 | vLLM | PagedAttention、Continuous Batching |
| 深入 | TensorRT-LLM | 算子融合、图优化、CUDA |
| 深入 | OpenVINO | 图优化 Pass、硬件适配 |
| 高级 | Apache TVM | 深度学习编译器、调度、代码生成 |
| 高级 | MLIR | 多级 IR、Dialect、Pass 框架 |
| 高级 | Halide | 算法调度分离、代码生成 |
| 高级 | Apache Arrow | 列式存储、零拷贝、IPC |
| 高级 | Paddle Lite | 多硬件 Kernel 优选、子图融合 |

我的建议是：

**先小后大，先机制后生态。**

不要一上来就啃 TVM 整仓，也不要一上来就研究 vLLM 全部特性。真正有效的方式是拆出最小闭环。

比如：

-   • 复刻 OpenBLAS，不是复刻全部 BLAS 接口，而是复刻一个 GEMM
    
-   • 复刻 llama.cpp，不是复刻全部模型支持，而是复刻一个 Transformer Block
    
-   • 复刻 Faiss，不是复刻全部索引类型，而是复刻 IVF + PQ
    
-   • 复刻 MLIR，不是复刻全部 Dialect，而是复刻一个 Dialect + 一个 Pass
    

## 三、怎么拆这些项目

面对几十万甚至上百万行的项目，最忌讳的学习方式是：

```
打开仓库
打开第一个 .cpp
从第一行开始读
三天后放弃
```

正确方法是先找最小主线。

### 3.1 先跑一个最小示例

不要先研究所有编译参数。

先完成一次最小运行：

```
输入是什么
经过了哪些模块
输出是什么
```

例如学习 llama.cpp，先跑通一条命令行推理。

学习 Faiss，先创建一个 Flat Index。

学习 MLIR，先让一个自定义 Operation 通过 `mlir-opt` 打印出来。

代码跑不起来时，架构图看得再多也容易停留在想象里。

### 3.2 找到核心数据结构

大型项目的灵魂，通常不在 API 名字里，而在数据结构里。

例如：

-   • llama.cpp：模型、上下文、Batch、KV Cache
    
-   • vLLM：Request、Sequence、Block Table
    
-   • ONNX Runtime：Graph、Node、Kernel、Session
    
-   • Faiss：Index、InvertedLists、Quantizer
    
-   • FreeRTOS：TCB、List、Queue
    
-   • Arrow：ArrayData、Buffer、Schema、RecordBatch
    

先看数据结构，再看函数。

因为函数会变，数据模型通常更稳定。

### 3.3 抓住一次完整执行流程

例如 ONNX Runtime：

```
加载模型
 ↓
构建计算图
 ↓
图优化
 ↓
选择 Execution Provider
 ↓
创建 Kernel
 ↓
内存规划
 ↓
执行
```

用 Debugger 或日志把整条流程走一遍。

不要第一次就钻进某个 AVX 指令或者 CUDA Kernel。

先建立地图，再进入街道。

### 3.4 给自己画三张图

建议至少画：

-   • 模块架构图
    
-   • 核心数据结构关系图
    
-   • 一次请求的执行时序图
    

很多源码之所以看不懂，不是代码太难，而是同时存在太多对象和状态。

把对象关系画出来，理解速度会明显提升。

### 3.5 删掉 90% 功能，重新写一个小版本

这一步最重要。

学习 vLLM，不需要先支持几十种模型。

只实现 Block Manager。

学习 TVM，不需要先支持所有硬件。

只实现循环分块和 C 代码生成。

学习 Arrow，不需要先支持 Parquet。

只实现整数列和空值位图。

学习 FreeRTOS，不需要先支持全部移植层。

只在 PC 上模拟任务状态机。

**读懂源码不等于掌握。**

能用自己的结构重新实现一遍，才算真正把设计思想拿走。

### 3.6 给复刻项目设计故障场景

正常运行只能证明主流程能走通。

故障场景才能暴露设计质量。

例如：

-   • KV Cache 不够怎么办
    
-   • 请求中途取消怎么办
    
-   • 模型文件损坏怎么办
    
-   • 图里出现未知算子怎么办
    
-   • 内存分配失败怎么办
    
-   • 推理任务超时怎么办
    
-   • 数据存在空值怎么办
    
-   • 多线程同时访问索引怎么办
    

优秀开源项目里，很多代码不是为了正常情况，而是为了处理边界和失败。

### 3.7 一定要做性能测量

学习 AI 基础设施，不能只看结果对不对。

还要看：

-   • 延迟
    
-   • 吞吐量
    
-   • 峰值内存
    
-   • 显存占用
    
-   • Cache Miss
    
-   • CPU 利用率
    
-   • GPU 利用率
    
-   • 首 Token 延迟
    
-   • 每秒生成 Token 数
    
-   • 向量检索召回率
    

例如优化 GEMM 后，不要只说“感觉快了”。

应该输出：

```
基础版本：120 ms
循环交换：78 ms
Cache Blocking：31 ms
SIMD：12 ms
SIMD + 多线程：4.8 ms
```

性能工程最怕的就是凭感觉。

## 四、项目背后的通用思想

### llama.cpp 和 ggml 教你

> 如何在有限内存下组织大模型推理。

### TensorRT-LLM 和 vLLM 教你

> 如何把 GPU、显存和并发请求调度起来。

### ONNX Runtime 和 OpenVINO 教你

> 如何让统一计算图适配不同硬件。

### TVM、MLIR 和 Halide 教你

> 如何把计算表达、优化策略和目标代码分层。

### OpenBLAS 教你

> 如何围绕处理器存储层次设计高性能代码。

### Faiss 教你

> 如何在速度、精度和内存之间进行系统权衡。

### Apache Arrow 教你

> 数据格式本身也是基础设施。

### FreeRTOS 教你

> AI 模型只是产品中的一个任务，而不是整个产品。

## 五、总结

拆解复刻这些项目，目标不是重复造轮子，而是读懂顶级开发者如何解决高性能、内存受限、异构硬件、并发调度等硬核问题。 当你吃透这套C/C++ AI技术栈底层实现，你将不再只是普通应用开发工程师，能够胜任AI底层框架优化、端云模型部署、异构系统设计等高价值岗位。

不要为了“看懂源码”而看源码。

复刻项目真正的价值是：**把优秀项目中的核心思想，用自己的代码重新实现一遍。**
