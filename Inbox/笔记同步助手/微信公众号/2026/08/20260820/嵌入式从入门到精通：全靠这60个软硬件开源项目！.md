我们学习嵌入式，最开始都是从单片机点灯开始的。

点个 LED、读个按键、配个串口，再往后可能会写 ADC、PWM、I2C、SPI，接几个传感器，跑个 FreeRTOS。

但很多人学到一定阶段之后，都会遇到一个问题：

**代码写了不少，板子也玩了不少，可一旦脱离厂商例程，就不知道一个真正的嵌入式系统应该怎么搭起来。**

这是因为完整的嵌入式开发，远远不只是“会写 STM32”。

它背后至少包含：

-   • MCU 启动之后，程序是怎么跑起来的
    
-   • 中断、任务、调度器是怎么工作的
    
-   • HAL、BSP 和设备驱动到底应该怎么分层
    
-   • Flash、文件系统和参数存储怎么设计
    
-   • TCP/IP、CAN、Modbus、USB 协议栈怎么组织
    
-   • Bootloader 和 OTA 为什么比想象中复杂
    
-   • Linux 内核、U-Boot 和 Rootfs 是怎么拼成一个系统的
    
-   • GDB、OpenOCD 到底是怎么控制芯片暂停和单步的
    
-   • PCB、FPGA、调试器这些硬件工具背后是什么原理
    
-   • 一个真正能量产的嵌入式产品，如何处理异常、升级、恢复和测试
    

如果只是跟着视频敲代码，这些东西很容易一直是黑盒。

**而深度学习优秀的软硬件开源项目，是建立嵌入式系统能力最快的一条路。**

因为成熟的开源项目，已经把大量工程问题真正解决过一遍。

你可以直接从里面看到：

```
启动代码
   ↓
BSP
   ↓
驱动
   ↓
RTOS
   ↓
协议栈
   ↓
中间件
   ↓
应用
   ↓
升级与诊断
```

更重要的是，你能看到这些模块之间到底应该怎么解耦。

**下面分享 60 个非常值得嵌入式开发者研究、拆解甚至自己复刻一遍的软硬件开源项目。**

## 一、MCU 与底层开发

### 1.1 libopencm3

libopencm3 是一个面向 ARM Cortex-M 系列 MCU 的开源底层库。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/3f872be888bcad0b5898244d7afc9fd9_MD5.jpg]]

```
项目地址：https://github.com/libopencm3/libopencm3
```

> 核心关键词：寄存器、外设驱动、Cortex-M、裸机开发

> 开源协议：LGPL-3.0-or-later

> GitHub 星标数： 3.6k

> 复刻建议：GPIO + UART + Timer + NVIC

很多人学习 STM32，一开始用的都是 HAL：

```
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET);
```

用起来很方便。

但问题是你很难知道底下到底发生了什么。

libopencm3 更接近：

```
寄存器
  ↓
外设抽象
  ↓
驱动 API
```

它非常适合从厂商 HAL 进一步向底层迈一步。

**真正值得学的不是怎么再写一套 GPIO API，而是驱动层应该如何把寄存器细节封装起来。**

**建议实践：** 选一块 STM32 开发板，不使用 HAL，基于 libopencm3 完成 GPIO、UART、定时器和外部中断，并对照参考手册追踪每个 API 最终修改了哪些寄存器。

### 1.2 CMSIS

CMSIS 是 ARM 为 Cortex-M 软件生态设计的一套标准接口。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/4fa2e7baf071907adc8d06ddad2bd1ac_MD5.jpg]]

```
项目地址：https://github.com/ARM-software/CMSIS_6
```

> 核心关键词：Cortex-M、NVIC、SysTick、启动代码、DSP

> 开源协议：Apache-2.0

> GitHub 星标数： 455

第一次打开 STM32 工程，经常能看到：

```
SystemInit();
NVIC_EnableIRQ();
__disable_irq();
__WFI();
```

这些东西很多并不是 STM32 独有的。

而是来自 ARM Cortex-M 的统一软件接口。

研究 CMSIS，你会真正理解：

```
MCU厂商
   ↓
CMSIS
   ↓
Cortex-M 内核
```

它是芯片厂商和 CPU 架构之间的一层标准化接口。

**建议实践：** 从一个空工程开始，只使用 CMSIS 手工搭建 Cortex-M 最小程序，完成启动文件、向量表、SystemInit、SysTick 和 NVIC 中断配置，真正跑通一次 MCU 从复位到 `main()` 的完整启动链。

### 1.3 STM32Cube

STM32Cube 是 ST 官方的 MCU 软件生态。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/e341193ec8507bbad6cc9663f96f0d88_MD5.jpg]]

```
项目地址：https://github.com/STMicroelectronics/STM32CubeF4
```

> 核心关键词：HAL、LL、BSP、Middleware

> 开源协议：混合许可（Apache-2.0 / BSD-3-Clause / SLA0044 等）

> GitHub 星标数： 1.3k

STM32Cube 最大的学习价值，不是 CubeMX 点几下自动生成代码。

而是理解一个成熟 MCU SDK 是怎么组织的：

```
CMSIS
  ↓
HAL / LL
  ↓
BSP
  ↓
Middleware
  ↓
Application
```

建议重点对比 HAL 和 LL。

你会发现：

**HAL 解决的是可移植性和开发效率，LL 解决的是更接近硬件的控制。**

**建议实践：** 用同一块 STM32 分别基于 HAL 和 LL 实现 GPIO、UART、Timer 和 ADC，对比两套代码的执行流程、代码体积和可读性，理解什么时候应该用 HAL，什么时候应该下沉到 LL。

### 1.4 ESP-IDF

ESP-IDF 是 Espressif 官方的 ESP32 开发框架。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/4d48362f0bcc991ab497528b6ab89261_MD5.jpg]]

```
项目地址：https://github.com/espressif/esp-idf
```

> 核心关键词：Wi-Fi、FreeRTOS、组件系统、IoT

> 开源协议：Apache-2.0

> GitHub 星标数： 18.8k

如果你想看一个“真正产品级”的 MCU SDK，ESP-IDF 非常值得研究。

它不只是几个驱动。

而是一整套：

```
Bootloader
   ↓
RTOS
   ↓
驱动
   ↓
网络协议栈
   ↓
Wi-Fi / BLE
   ↓
组件系统
   ↓
应用
```

尤其值得学习的是它的 component 机制。

一个大型嵌入式工程，最后一定会遇到模块化问题。

ESP-IDF 就是很好的教材。

**建议实践：** 用 ESP32 做一个完整的 Wi-Fi 传感器节点，把驱动、网络、存储和应用分别拆成独立 Component，并加入 NVS 参数保存和 OTA 升级，体验一次产品级 MCU 工程的目录与模块设计。

### 1.5 Raspberry Pi Pico SDK

Pico SDK 是 RP2040 / RP2350 的官方 C/C++ SDK。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/f517635ae8e388b0fd5b7f3f4fa37e21_MD5.jpg]]

```
项目地址：https://github.com/raspberrypi/pico-sdk
```

> 核心关键词：双核 MCU、PIO、CMake、裸机

> 开源协议：BSD-3-Clause

> GitHub 星标数： 4.9k

Pico SDK 最有意思的地方，是 RP2040 的 PIO。

很多协议原本需要 CPU bit-banging：

```
CPU
 ↓
GPIO翻转
 ↓
严格控制时序
```

PIO 把这件事变成：

```
CPU
 ↓
PIO状态机
 ↓
GPIO
```

本质上是在 MCU 里塞了一个专门处理 IO 时序的小型可编程状态机。

非常值得研究。

**建议实践：** 使用 RP2040 的 PIO 独立实现一次严格时序协议，例如 WS2812 灯带驱动，并用逻辑分析仪观察波形，对比 CPU bit-banging 与 PIO 状态机方案的区别。

### 1.6 Arduino Core

Arduino 真正值得看的不是 `digitalWrite()`。

而是它怎么把复杂 MCU 硬件封装成一个极简单的 API。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/f500ee74291d7c725a648bb2a3756b61_MD5.jpg]]

```
项目地址：https://github.com/arduino/ArduinoCore-avr
```

> 开源协议：LGPL-2.1-or-later（核心代码；仓库含其他许可）

> GitHub 星标数： 1.5k

例如：

```
pinMode(13, OUTPUT);
digitalWrite(13, HIGH);
```

背后实际上需要：

```
引脚编号
 ↓
端口映射
 ↓
DDR寄存器
 ↓
PORT寄存器
```

**真正值得学习的不是 Arduino 有多简单，而是它如何把复杂度藏起来。**

**建议实践：** 绕过 `digitalWrite()` 和 `pinMode()`，自己根据 Arduino 引脚映射表实现一个 mini GPIO API，再对比 Arduino Core 源码，弄清楚一个简单 API 背后是如何完成端口和寄存器映射的。

## 二、RTOS：真正理解任务、调度、中断和同步

### 2.1 FreeRTOS

FreeRTOS 几乎是嵌入式开发者绕不开的 RTOS。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/f98c844998468046b1cf97b7c5159aeb_MD5.jpg]]

```
项目地址：https://github.com/FreeRTOS/FreeRTOS-Kernel
```

> 开源协议：MIT GitHub 星标数： 4.4k

> 复刻建议：自己实现 task + ready list + tick + context switch

最值得学习的是：

```
Task
 ↓
Ready List
 ↓
Scheduler
 ↓
PendSV
 ↓
Context Switch
```

很多人会用：

```
xTaskCreate();
vTaskDelay();
xQueueSend();
```

但不知道任务为什么能切换。

如果把 FreeRTOS 调度器最核心的一条链跑通，你会真正理解 RTOS。

**建议实践：** 做一个包含传感器采集、数据处理、串口输出三个任务的小系统，实际使用 Queue、Semaphore 和 Mutex，再通过 SysTick 和 PendSV 调试任务切换过程，把一次完整的上下文切换真正看明白。

### 2.2 Zephyr

Zephyr 是一个大型模块化实时操作系统。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/b4a0ca54d694fd188163b2df77f92b52_MD5.jpg]]

```
项目地址：https://github.com/zephyrproject-rtos/zephyr
```

> 开源协议：Apache-2.0

> GitHub 星标数： 16.2k

它最大的价值，是展示了现代嵌入式操作系统如何处理：

-   • Kconfig
    
-   • Devicetree
    
-   • Driver Model
    
-   • Board
    
-   • SoC
    
-   • Kernel
    
-   • Subsystem
    

很多人第一次看 Zephyr 会觉得复杂。

但它实际上是在解决一个问题：

> **几百种开发板、几十种架构、几千个驱动，怎么放进同一套系统？**

**建议实践：** 给 Zephyr 添加一块自定义开发板，并通过 Devicetree 接入一个 I2C 或 SPI 传感器，自己写最小驱动，让应用层通过统一 Device API 调用它，完整走一遍 Board → Devicetree → Driver → Application。

### 2.3 RT-Thread

RT-Thread 是国内非常成熟的一套开源 RTOS。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/0e9211cc16cfafd3693d0b7077de7313_MD5.jpg]]

```
项目地址：https://github.com/RT-Thread/rt-thread
```

> 开源协议：Apache-2.0

> GitHub 星标数： 12.2k

它非常适合从 MCU 开发向“嵌入式操作系统”过渡。

尤其值得看：

```
Kernel
 ↓
Device
 ↓
Component
 ↓
FinSH
 ↓
Package
```

RT-Thread 的设备框架很有学习价值。

因为嵌入式系统做到后期，一定不能让应用层到处直接操作 HAL。

**建议实践：** 在 STM32 上运行 RT-Thread，自己实现一个传感器 Device Driver，并通过 FinSH 命令读取设备数据和修改参数，体会应用层不直接调用 HAL 后，设备框架带来的工程价值。

### 2.4 Apache NuttX

NuttX 是一个很像“小型 Linux”的 RTOS。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/5ea0507f583f6011e05b706ecbb6c588_MD5.jpg]]

```
项目地址：https://github.com/apache/nuttx
```

> 开源协议：Apache-2.0

> GitHub 星标数： 4.0k

它支持：

-   • POSIX 接口
    
-   • 文件系统
    
-   • 网络
    
-   • 驱动模型
    
-   • Shell
    
-   • 多种 MCU
    

如果你已经学过 FreeRTOS，NuttX 很适合作为下一阶段。

因为它会让你第一次真正感受到：

**RTOS 也可以有操作系统味道。**

**建议实践：** 在 STM32 或 QEMU 上启动 NuttX，自己实现一个最简单的字符设备驱动，再从用户态通过 `open()`、`read()`、`write()` 访问它，体验一次“小型 Linux”式的驱动开发流程。

### 2.5 Eclipse ThreadX

ThreadX 是工业界使用非常广泛的实时操作系统。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/15dea9aca1063c9b490e18aca5662926_MD5.jpg]]

```
项目地址：https://github.com/eclipse-threadx/threadx
```

> 开源协议：MIT

> GitHub 星标数： 3.5k

值得学习：

-   • 优先级调度
    
-   • Event Flags
    
-   • Message Queue
    
-   • Memory Pool
    
-   • Thread 状态管理
    

尤其建议研究它的内存池。

很多 MCU 项目并不适合大量使用普通 `malloc()`。

固定块内存池通常更加稳定。

**建议实践：** 设计一个固定周期的数据采集系统，用 ThreadX 的 Message Queue 在线程间传递数据，并使用 Memory Pool 管理固定大小的数据块，对比它和 `malloc()` 在实时系统中的差别。

### 2.6 RIOT

RIOT 是面向 IoT 设备设计的开源操作系统。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/73c46fb1194179576e3b011a70860178_MD5.jpg]]

项目地址：https://github.com/RIOT-OS/RIOT
```

> 开源协议：LGPL-2.1

> GitHub 星标数： 5.8k

它最大的特点是：

**在资源受限 MCU 上，也尽量提供类似现代操作系统的开发体验。**

尤其适合学习：

线程
网络
IPv6

```

**建议实践：** 准备两到三块支持 RIOT 的 MCU 开发板，建立一个 IPv6/6LoWPAN 小网络，让节点通过 UDP 或 CoAP 相互通信，并观察低功耗 IoT 网络中数据是如何逐层传递的。

## 三、GUI、USB、存储：把一个 MCU 真正做成产品

### 3.1 LVGL

LVGL 是嵌入式 GUI 领域最值得学习的项目之一。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/b53225b0466e8719f5c1d0c92c1f4296_MD5.jpg]]

```
项目地址：https://github.com/lvgl/lvgl
```

> 开源协议：MIT

> GitHub 星标数： 24.4k

很多人以为 GUI 就是画按钮。

其实真正难的是：

```
Widget
 ↓
Layout
 ↓
Style
 ↓
Event
 ↓
Invalid Area
 ↓
Render
 ↓
Display Driver
```

LVGL 的核心价值，就是把 GUI 做成了一套完整对象系统。

**建议实践：** 做一个完整的小型设备 HMI，包含主页、设置页、实时曲线、按钮和弹窗，并把显示驱动、触摸驱动和业务逻辑分层，最终在 STM32 或 ESP32 实机上运行。

### 3.2 u8g2

u8g2 是非常经典的单色屏图形库。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/970218dc637bc1e8f6f1ef50b93dd4e2_MD5.jpg]]

```
项目地址：https://github.com/olikraus/u8g2
```

> 开源协议：BSD-2-Clause

> GitHub 星标数： 6.6k

如果 LVGL 太复杂，可以先研究 u8g2。

特别适合理解：

-   • Frame Buffer
    
-   • 字体编码
    
-   • 点阵字库
    
-   • I2C / SPI 屏幕接口
    
-   • 图形裁剪
    

自己写一个字符绘制函数之后，你会发现：

**所谓 GUI，本质上首先是一堆像素。**

**建议实践：** 用 OLED 做一个迷你设备仪表盘，自己实现数字、中文、图标和实时数据刷新，并尝试不同 Buffer 模式，实际观察 RAM 占用和刷新速度之间的关系。

### 3.3 TinyUSB

TinyUSB 是一个面向 MCU 的 USB Host / Device 协议栈。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/ae9bacca87ac518a38dbe022bbe435e8_MD5.jpg]]

```
项目地址：https://github.com/hathach/tinyusb
```

> 开源协议：MIT

> GitHub 星标数： 7.0k

USB 是非常值得深入一次的协议。

你会真正接触：

```
Descriptor
 ↓
Endpoint
 ↓
Control Transfer
 ↓
Enumeration
 ↓
Class Driver
```

学完 TinyUSB，再看 USB CDC、HID、MSC，就不再只是复制例程。

**建议实践：** 用一块支持 USB Device 的 MCU 做一个复合 USB 设备，同时实现 CDC 虚拟串口和 HID 键盘或自定义 HID，并用电脑查看 Descriptor 和枚举过程。

### 3.4 littlefs

littlefs 是为 MCU Flash 设计的小型文件系统。

![[Inbox/笔记同步助手/微信公众号/2026/08/images/b805998d36546f997b1722f1efa0cf3a_MD5.jpg]]

```
项目地址：https://github.com/littlefs-project/littlefs
```

> 开源协议：BSD-3-Clause

> GitHub 星标数： 6.9k

嵌入式文件系统真正困难的地方，不是“怎么保存一个文件”。

而是：

> **写到一半突然掉电怎么办？**

littlefs 非常值得学习：

-   • 掉电恢复
    
-   • 磨损均衡
    
-   • 元数据管理
    
-   • Flash 擦写特性
    

**建议实践：** 在 SPI NOR Flash 上移植 littlefs，保存设备参数和运行日志，然后在连续写入过程中主动断电几十次，检查文件和参数能否正确恢复，真正验证掉电安全。

### 3.5 FatFs

FatFs 是嵌入式领域非常经典的 FAT 文件系统。

```
项目地址：http://elm-chan.org/fsw/ff/
```

## 十一、这60个项目应该怎么学？

这 60 个项目，不建议按照文章顺序全部下载下来。

那样很容易变成：

```
clone
 ↓

 ↓
吃灰
```

更有效的方法，是按照自己能力层级学习。

| **阶段推荐项目核心能力** | <br> | <br> |
| :-- | :-- | :-- |
| 入门 | Arduino、CMSIS、libopencm3 | MCU、寄存器、中断 |
| 入门 | FreeRTOS、RT-Thread | 任务、调度、同步 |
| 进阶 | LVGL、TinyUSB、littlefs | 中间件 |
| 进阶 | lwIP、Modbus、CANopen | 通信协议 |
| 进阶 | MCUboot、SWUpdate | Bootloader、OTA |
| 深入 | U-Boot、Buildroot、Linux | Embedded Linux |
| 深入 | OpenOCD、GDB、QEMU | 调试与仿真 |
| 高级 | Unity、CMock、Ceedling | 工程测试 |
| 高级 | KiCad、Yosys、nextpnr | 硬件与 FPGA |
| 综合 | OpenMV、HackRF、BeagleBone | 系统级产品 |

我的建议依然是：

**不要一上来追求“大而全”，先把一个最小闭环真正跑通。**

GPIO
UART
Timer
EXTI
```

不要 HAL。

直接基于寄存器和 CMSIS。

目标只有一个：

> 理解 MCU 外设驱动到底是什么。

### 第二个项目：mini RTOS

实现：

-   • Task Control Block
    
-   • Stack
    
-   • Ready List
    
-   • SysTick
    
-   • PendSV
    
-   • Round-Robin
    

不需要实现 Queue、Semaphore、Timer。

先让两个任务真正切换起来。

做到这里，你才算真正理解：

**所谓 RTOS，最核心就是保存现场和恢复现场。**

### 第三个项目：mini 文件系统

找一块 SPI Flash。

实现：

```
block_read()
block_write()
block_erase()
 ↓
KV存储
 ↓
掉电恢复
```

甚至不一定需要完整文件系统。

先理解存储系统为什么需要：

-   • CRC
    
-   • 双备份
    
-   • Version
    
-   • Commit
    

### 第四个项目：mini Bootloader

Flash 划分：

```
Bootloader
Application A
Application B
Config
```

然后实现：

```
检查升级标志
 ↓
检查固件
 ↓
CRC
 ↓
跳转
 ↓
失败回滚
```

做到这里，你已经开始从“玩开发板”进入“做产品”。

### 第五个项目：mini TCP Server

使用 lwIP。

只追一条链：

```
Ethernet IRQ
 ↓
Driver
 ↓
pbuf
 ↓
IP
 ↓
TCP
 ↓
Application
```

然后用 Wireshark 看数据。

**千万不要只看源码。**

网络协议一定要：

```
源码
+
抓包
```

一起看。

### 第六个项目：mini Linux

自己组合：

```

+
Linux Kernel

+

```

然后用 QEMU 跑起来。

看到：

```

这个 Shell 的时候，你会第一次真正理解：

**Linux 发行版并不是一个神秘整体，它本质上就是很多组件被组合在一起。**

## 十三、研究开源项目最有效的方法

### 1\. 不要从 main.c 第一行开始看

大型项目最容易犯的错误就是：

```
打开源码
 ↓
找到main
 ↓
逐行阅读
 ↓
三小时后不知道自己在看什么
```

更好的方法是先问：

> 我到底想弄懂哪一条执行链？

比如 FreeRTOS：

```
SysTick
 ↓
xTaskIncrementTick
 ↓
Scheduler
 ↓
PendSV
 ↓
Context Switch
```

只追这一条。

### 2\. 先找数据结构

一个成熟软件项目，真正的设计思想往往藏在数据结构里。

比如 RTOS：

```
TCB
List
Queue
```

Linux：

```
task_struct
file
inode
device
```

LVGL：

```
Object
Style
Event
Display
```

CANopen：

```
Object Dictionary
PDO
SDO
Node
```

先看数据结构，再看函数，理解速度通常快很多。

### 3\. 一定要画图

至少画四类图。

**模块图**

回答：

> 系统由哪些部分组成？

**时序图**

回答：

> 一个事件是怎么流动的？

**状态机**

回答：

> 系统有哪些状态？

**数据结构关系图**

回答：

> 对象之间怎么连接？

例如 OTA：

```
IDLE
 ↓
DOWNLOADING
 ↓
VERIFYING
 ↓
INSTALLING
 ↓
REBOOT
 ↓
CONFIRM
```

如果失败：

```
ROLLBACK
```

一张状态图，往往比看 3000 行源码更加有用。

### 4\. 学会“删代码”

复刻一个开源项目，不是把代码抄一遍。

而是应该主动删掉：

-   • 多平台兼容
    
-   • 历史兼容
    
-   • 极端优化
    
-   • 冷门功能
    
-   • 完整配置系统
    
-   • 大量异常分支
    

只留下：

```
核心数据结构
+
核心状态机
+
核心执行链
+
最小输入
+
最小输出
```

这才叫复刻。

### 5\. 主动制造故障

真正的嵌入式工程能力，很多时候不是从正常流程里练出来的。

你应该主动测试：

-   • I2C 设备突然拔掉
    
-   • Flash 写一半断电
    
-   • TCP 连接突然断开
    
-   • CAN 总线出现 Bus-Off
    
-   • Task 发生死锁
    
-   • Heap 耗尽
    
-   • Bootloader 收到损坏固件
    
-   • OTA 升级后应用启动失败
    
-   • Linux Rootfs 损坏
    
-   • 子进程突然崩溃
    

然后观察：

```
系统还能不能恢复？
状态有没有错乱？
资源有没有泄漏？
错误能不能定位？
重启之后还能不能继续工作？
```

**Demo 看正常流程，产品看异常流程。**

这两者之间的差距，往往就是嵌入式初学者和成熟工程师之间最大的差距。

## 十四、总结

学习嵌入式最大的误区之一，就是把它理解成：

> STM32 + C语言 + 几个外设。

真正的嵌入式系统，其实横跨了非常多领域：

```
CPU架构
+
MCU
+
RTOS
+
驱动
+
文件系统
+
通信协议
+
Bootloader
+
Linux
+
网络
+
安全
+
测试
+
PCB
+
FPGA
```

所以真正有效的学习方式，也不是不断换开发板、不断跟着视频做 Demo。

而是找几个足够优秀的开源项目，顺着它们已经验证过的工程设计，一层一层拆。

你不需要把这 60 个项目全部看完。

如果能真正吃透其中 10 个，并且自己实现过几个 mini 版本，你对嵌入式系统的理解就会发生非常明显的变化。

你会从：

> 会调用 HAL。

逐渐变成：

> 知道 HAL 为什么这样设计。

再变成：

> 自己也能设计一套 BSP、驱动、中间件和系统架构。

最后，你会发现：

**嵌入式开发所谓的“精通”，并不是记住多少 API。**

而是面对一块陌生芯片、一套陌生系统或者一个复杂 Bug 时，你知道应该从哪一层开始拆，知道数据是怎么流动的，也知道问题最可能藏在哪里。

这才是真正的嵌入式系统能力。
